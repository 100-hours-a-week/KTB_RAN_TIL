  - **두자리를 정하여**
    - 인접하지 않는 두 수
  - **세자리를 정하여**
    - cow2, carry 피하기
  - **격자 위에서 가장 좋은 위치**
    - 격자 위 연속
      1. 격자에서 방향 탐색이 나오면 dx, dy를 먼저 생각한다.
         - **격자라고 했을때 가장 먼저 떠올릴 것.**
           ```python
           # 격자 이동 BFS/DFS
           dx = [0, 0, -1, 1]
           dy = [-1, 1, 0, 0]

           # 격자 8방향
           dx = [0, 0, -1, 1, -1, 1, -1, 1]
           dy = [-1, 1, 0, 0, -1, -1, 1, 1]

           # 오목/연속 직선 확인 : 위 아래 대각선오른쪽아래 대각선오른쪽위
           dx = [1, 0, 1, 1]
           dy = [0, 1, 1, -1]

           #격자 코드 구조 (거의 고정)

           모든 행 확인
           모든 열 확인
           각 칸에서 필요한 방향 탐색

           for c_y in range(n):
               for c_x in range(n):
                   for x,y in zip(dx,dy):
                       nx = c_x + x
                       ny = c_y + y
           ```
      2. 격자에서 연속 문제는 **모든 칸 × 방향 × step** 구조를 잊지 말것.
         - 코드
           ```python
           for d in range(4):
                       cnt = 1

                       for step in range(1, 5):
                           nx = x + dx[d] * step
                           ny = y + dy[d] * step

                           if in_range(nx, ny) and board[ny][nx] == color:
                               cnt += 1
                           else:
                               break
           ```
      3. 모든 칸을 시작점으로 잡고 확인한다.

         ```python
         모든 행 확인
         모든 열 확인
         각 칸에서 필요한 방향 탐색
         ```

      4. 상태 관리
         - 방향 하나마다 cnt를 새로 만들어야 한다.

# TIL 단어 정리

- **GC 가비지 컬렉터**
  - 사용하지 않는 객체 즉, 참조하지 않는 객체를 삭제 시켜준다.
- **JS 힙**
  - 컴포넌트에서 만들어진 객체.
  - 힙은 자체로 JAVA에도 있는데, 컴포넌트에서 만들어진 객체가 저장되는 곳이다.
  - GC가 관리한다.
- **GPU 메모리** (그래픽 카드 메모리)
  - 캔버스에 적힌 요소들이 저장되는 곳
  - **GC는 GPU 메모리를 관리하지 않는다.**
    - JS 엔진입장에선 GPU는 외부 자원이기 때문
  - GPU와 JS의 비교
    - JS 객체 : 종이에 적은 메모 (책상 어질러놔도 엄마가 정리해줌)
    - GPU : 컴퓨터에 저장한 메모 (엄마는 컴퓨터를 잘 몰라서 정리 못해줌)
      - 엄마한테 “컴퓨터에 있는 거 삭제 해줘” == dispose()
      - 개발자가 명시적으로 dispose를 호출하지 않으면 GPU메모리가 정리 되지 않음
- **[WebGL] Canvas**
  - Canvas가 `<canvas>` DOM 요소를 통해 GPU에게 "이 도형 데이터, 이 텍스처를 그래픽카드 메모리에 올려줘"라고 명령함.
  - Canvas 언마운트 시
    - **JS 쪽**: React가 트리를 정리하니까 컴포넌트 객체들은 GC 대상이 됨
    - 예상 : GPU 메모리에 저장되어 있던 요소들을 없앤다
      - WebGL 컨텍스트는 사라질 수 있어도, 개별적으로 업로드 해줬던 texture, geometry 버퍼는 사라지지 않을 수 있다.
- **[WebGL] Draw Call**
  - 드로우 콜 : CPU가 그리라고 GPU한테 명령함.
  - 작가한테 “A그림 그려주세요.”라고 명령함.
  - 작가가 그리는 시간은 빠름. 근데 명령 1건당 준비 비용이 듬.
    - 예시 ) 작가님 A 마감 10분만에 그림 근데 집찾아가는데 1시간걸림 (준비비용)
      - A,B,C,D 그림 그려달라고 10번 준비하면서 찾아가서 말하는 것보다(준비비용)*10, A,B,C,D 그려주세요 라고 한꺼번에 말하는게 더 빠르겠죠? (준비비용)*1 ← 이렇게 한번에 부탁하는걸 **instancing** 이라고 함.
    - 3D에서 "draw call을 줄이자"가 고전적인 최적화 주제
- **[WebGL]instancing**
  - 같은 오브젝트를 단 한번의 draw call 로 그리도록함.
    일반: 나무 1000개 → draw call 1000건
    Instancing: 나무 1000개 → draw call 1건 + 위치 1000개 배열
- **Suspense란?**
  요청했는데 아직 준비가 안 된 자식 컴포넌트 대신 `fallback`을 보여주는 기능
  ```python
  <Suspense fallback={<div>Loading...</div>}>
    <ConversationContent />
  </Suspense>
  ```
